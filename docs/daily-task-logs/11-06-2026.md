* configured S3 bucket for frontend hosting with private access
* set up CloudFront distribution for global frontend delivery
* deployed React build automatically using CDK BucketDeployment
* integrated API Gateway with Lambda backend for `/chat` and `/health`
* implemented API key authentication for `/chat` endpoint using `x-api-key`
* configured CORS headers for frontend and API Gateway communication
* verified end-to-end flow: React → API Gateway → Lambda → RAG pipeline → response
* ensured secure separation of public `/health` and protected `/chat` endpoints

## Issues Faced

* frontend showed “Access Denied” after deployment

  > caused by missing `index.html` root object in CloudFront configuration and initial S3 access setup mismatch

* API access blocked from frontend due to CORS errors

  > fixed by adding `x-api-key` to allowed headers in API Gateway and ensuring Lambda response always included CORS headers

* confusion around CloudFront + S3 permissions

  > resolved by using CDK-managed `S3Origin` instead of manual bucket policies (CDK handles access internally)

---

## Learnings

* CloudFront requires `default_root_object = index.html` for React SPA apps
* S3 should remain private when using CloudFront (secure architecture pattern)
* CDK simplifies S3 + CloudFront integration by handling Origin Access automatically
* frontend `.env` variables are bundled at build time and are not secure for secrets
* API key authentication in frontend is only a basic protection layer (not true security)
* proper separation of public vs protected endpoints improves API design clarity
* full-stack debugging requires isolating issues across CloudFront, API Gateway, and Lambda layers

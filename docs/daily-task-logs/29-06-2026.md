### Issues Faced

* DynamoDB rejected updates because `ttl` is a reserved keyword.

  > Fixed by using `ExpressionAttributeNames` (`#ttl`) inside `UpdateExpression`.

* Lambda failed to serialize DynamoDB responses due to `Decimal` values.

  > Added a recursive decimal conversion helper before returning API responses.

* Conversation history endpoint returned objects filled with `null` values.

  > Fixed the recursive conversion utility to correctly return dictionaries after conversion.

* Multiple backend unit and integration tests failed after replacing `sessionId` with `clientId` and `conversationId`.

  > Refactored test payloads, mocks, and assertions to match the new API contract.

* Frontend API client tests failed because error handling now throws structured objects instead of `Error` instances.

  > Updated mocks and assertions (`toMatchObject`) to match the new implementation.

### Learning

* DynamoDB reserved keywords require aliases via `ExpressionAttributeNames`.
* DynamoDB numeric attributes are returned as `Decimal` objects and must be converted before JSON serialization.
* Recursive conversion utilities must return converted dictionaries/lists explicitly to avoid accidentally returning `None`.
* Refactoring API contracts requires updating not only request payloads but also mocks, assertions, and integration test setup.
* Maintaining comprehensive automated tests during feature development significantly reduces regression risk after large architectural changes.

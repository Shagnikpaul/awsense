### Issues faced

**Error**

- `no such index [awsense-index]`



> Manually created missing OpenSearch vector index required by Bedrock Knowledge Base storage configuration



**Error**

- `The OpenSearch Serverless engine type associated with your vector index is invalid`

**Fix**

> Deleted manually created index and switched to AWS-managed vector store creation to ensure FAISS-compatible index generation


**Error**

- `Missing required parameter vectorIndexName`

**Fix**

> Added `vectorIndexName=awsense-index` in OpenSearch Serverless storage configuration during CLI-based attempts



**Error**

- `403 Forbidden / security_exception during ingestion`

**Fix**

> Updated OpenSearch Serverless data access policy to include correct Bedrock execution role permissions and aligned collection/index names with active KB configuration



**Error**

- `Too many requests (429) from Bedrock embedding model`

**Fix**

> Identified as temporary rate limiting on Titan embedding model; resolved by waiting before retrying ingestion job



### Learnings

* AWS Bedrock Knowledge Base requires strict alignment between:

  * S3 data source
  * OpenSearch Serverless collection
  * vector index configuration
  * IAM execution role permissions
* OpenSearch Serverless + Bedrock integration is highly sensitive to:

  * index naming consistency
  * policy propagation delays
  * automatic vs manual index creation conflicts
* “Quick create vector store” is preferred for development because it avoids FAISS/index compatibility issues
* 429 errors in Bedrock embedding calls are usually temporary throttling, not configuration issues
* Console-based setup is more reliable than CLI for initial KB creation due to hidden validation rules

## Issues Faced & Fixes

* **Conversation creation timing**

  > Decided to create a conversation only when the first message is successfully sent, avoiding empty conversations.

* **Conversation creation on failed requests**

  > Identified that backend/API failures could leave empty conversations. Current implementation keeps conversation creation before persistence, with future improvements possible if transactional behavior is needed.

* **React warning about `setState` inside `useEffect`**

  > Refactored initial conversation loading into an async function inside the effect instead of triggering state updates through another callback.

* **Unlimited history support**

  > Removed previous 5-turn message limit from the frontend state.

* **Missing API Gateway endpoints**

  > Identified and added `/conversations` and `/conversations/{conversationId}` support to infrastructure planning.

* **DynamoDB reserved keyword (`ttl`)**

  > Fixed `UpdateExpression` by using `ExpressionAttributeNames` (`#ttl`).

* **Decimal serialization errors**

  > Added recursive conversion of DynamoDB `Decimal` values before returning JSON responses.

* **Recursive conversion bug**

  > Fixed `convert_decimals()` to return primitive values instead of implicitly returning `None`, preventing `null` values in API responses.

* **Conversation loading returning `null` fields**

  > Root cause was the missing default `return value` in the recursive conversion helper.

* **Frontend/backend contract updates**

  > Ensured new request and response payloads matched across frontend, backend, and persistence layer.

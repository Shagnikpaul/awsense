## Week 3 (Updated -> 17-06-2026)


### Tasks done

* Migrated ingestion pipeline from flat URL list to grouped JSON structure with topic-wise AWS services (EC2, S3, IAM, etc.)
* Refactored metadata generator to attach topic during ingestion instead of inferring it from URLs
* Updated FAISS vector store builder to include topic inside every chunk’s source metadata
* Enhanced retriever with topic-aware query injection to improve embedding relevance for vague queries
* Implemented hard topic filtering in retrieval layer to prevent cross-topic leakage between AWS services
* Added fallback retrieval logic to avoid empty results after strict filtering
* Built and tested local retriever validation script to verify topic isolation and correctness
* Fixed production issue where Route 53 queries were incorrectly returning S3 results due to weak semantic matching

---

### Issues faced

* Vague queries like “what is it” or “usecases of this service” caused incorrect retrieval results due to weak semantic grounding in embeddings

> Fixed by injecting topic context into query before embedding and enforcing hard filtering after retrieval

* FAISS returned high-ranking but incorrect cross-topic chunks (e.g., S3 appearing in Route 53 queries)

> Fixed by increasing candidate pool (k * 10), applying strict topic filter, and adding fallback mechanism

* Initial design used post-retrieval filtering which allowed irrelevant documents to influence ranking

> Fixed by shifting toward pre-filtered semantic reinforcement through query enrichment

---

### Learnings

* Topic must be enforced at both ingestion and query level for robust RAG systems
* FAISS retrieval alone cannot guarantee domain correctness without structured metadata filtering
* Query enrichment significantly improves embedding quality for vague or incomplete user inputs
* Over-fetching (k * 10) + post-filtering is necessary when applying strict constraints
* Real-world RAG systems require fallback logic to prevent empty or broken responses
* Structured ingestion pipelines are critical for scalable multi-domain retrieval systems
